# Run 1101 包数扫描解读

这是一轮已保存 IQ 的离线回放。训练只使用时隙 0–59 中两侧各自恢复的包；验证固定为时隙 60–99 中双方共同恢复的 19 个包。模型在时隙 60 前冻结，后续所有验证包都未参与拟合。发送端以 200 ms 为计划时隙间隔；`ref_tick_ms` 是计划时间，非实测 RF 起点。

`natural` 保留两侧实际收到的训练包；`disjoint` 从 ZigBee 训练集中排除 BLE 使用的训练时隙，代表“两个接收端依靠不同包”的回放条件。后者是离线屏蔽，不能视为第二轮物理采集。完整时隙选择和逐包结果见同目录 CSV。

两包拟合时，两点相距很近，单次发射时刻抖动会被放大为速率误差。例如 `disjoint` 两包配置的 BLE 训练包跨 400 ms，ZigBee 跨 200 ms，估计的相对标称速率偏差分别达到约 +356 ppm 和 −1,077 ppm；这些不是可信的晶振参数。多包拟合降低了这类偶然误差，但数字并未随包数单调变化，因为每个 K 使用不同的历史时隙、覆盖跨度和最近更新时间。`natural` 的 1–2 包结果特别小，两侧训练包完全重合，具有共同发射误差，不能代表不同收包条件。

验证误差是两侧独立时间模型对**各自包标记处**的共同 RF 事件估计出的时间之差。两个标记在同一包内存在固定位置差，且接收链固定延迟和传播差未独立校准，模型会吸收这些常数。因此本表只检验相对估计的一致性，不是绝对同步误差、软件执行时差或发射端计划时刻误差。19 个验证包不足以给出可靠 P99；一轮有效录制也不足以估计跨轮不确定度。

这轮支持的结论是：即使两侧训练包不重合，利用一段时间内较多有效包仍可得到相近的共同时间估计；仅凭相邻两个包估计速率非常不稳。下一步应在更多独立录制上固定训练跨度和更新年龄，再单独扫描有效包数，并校准包内标记差及计划时间到实际 RF 起点的误差。
