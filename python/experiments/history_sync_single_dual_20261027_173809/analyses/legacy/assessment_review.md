# Run 10272：首次完整单台—双台—单台实验评估

结论：本轮三阶段完整执行，双设备能同时恢复同一轮的正确测试负载，没有重现 USB 断连和 ZigBee 零接收。已具备继续进行独立双端可靠性及时间轴校准实验的条件。但单轮结果不证明长期稳定、双台无性能影响或已经实现设备间同步。

## 配置与采集完整性

记录目录：`python/sync_validation/results/single_dual_20261027_173809`。Run ID 10272、payload 30 B、板端命令记录为 `bluebee_exadv_perf_start?30 200000 0 10272`。持续发送跨阶段递增 Sequence，板端真实计数未合并。

- ZigBee 设备末尾 3348a6c3，BLE 设备末尾 2926a0c3；固定接收 2480 MHz。
- ZigBee 使用 `phase/project`、低通截止 700 kHz、DC 抑制 1 kHz；BLE 使用既有 850 kHz 配置。
- 两侧输入均为 8 Msps，三段各 30 s；共四份 IQ，各 480,000,000 B，共 1.92 GB。
- 所有接收进程、`hackrf_transfer` 均正常退出；每路处理 240,000,000 个复数样本。
- 实时队列最高：单台前 3/64、双台 ZigBee 3/64、双台 BLE 3/64、单台后 2/64，无应用队列溢出报告。
- 查询 17:38:05..17:40:00 的内核日志，没有发现 USB 事件；设备日志也没有本轮断连/重新枚举错误。此证据限定于本轮，不保证所有硬件采样都无缺口或今后不再发生间歇故障。

## 三段 ZigBee 结果

全部 307 个 ZigBee 有效帧重新计算 FCS，并检查 Run ID、Sequence 和完整确定性填充，均通过。

| 阶段 | 录制时间 | 唯一有效包 | 收到的 Sequence 范围 | 范围内最长连续缺失 | Application goodput |
| --- | --- | --- | --- | --- | --- |
| single_before | 30 s | **104** | 17..166 | 4 | 69.33 B/s，554.67 bit/s |
| dual | 30 s | **95** | 171..320 | 4 | 63.33 B/s，506.67 bit/s |
| single_after | 30 s | **108** | 326..474 | 3 | 72.00 B/s，576.00 bit/s |

重复、乱序、测试填充失败和 Run ID 不匹配均为 0。最长缺失的口径是各阶段已接收最小到最大 Sequence，不包含未知首尾。

gross throughput 分别为 104/95/108 B/s，即 832/760/864 bit/s。分母均为完整 30 s IQ，application 扣除每包 10 B 测试头。

两次单台的平均为 106 包，双台 95 包，少 11 包，约低 10.4%。这只是本轮描述性差异：三个阶段并非同时测量，payload Sequence 不同，也只有一次 ABA，不能排除时间变化、空间衰落或其他条件的影响，不能宣布存在或不存在稳定的双台性能损失。

按每 5 s 分箱，三段有效包数为：

没有出现双台全段停收。若后续持续观察到相同方向的下降，应交替单/双顺序独立重复，而不是将本轮所有包直接当作独立样本做显著性检验。

## 双台联合解码

BLE 共报告 677 个 CRC 有效 PDU，其中 599 个 primary、78 个目标 secondary。78 个目标包均从 BLE 自身已解码字节中解析并通过内嵌 PHY FCS 与完整测试填充校验，Run ID 10272、payload 30 B，无重复。

将 BLE 78 个与另一块设备实时 ZigBee 恢复的 95 个按 Run ID+Sequence 匹配，并检查完整 PHY 帧逐字节相同：

| 结果 | 数量 |
| --- | --- |
| 两侧共同有效 | **76** |
| 仅 BLE 有效 | 2 |
| 仅 ZigBee 有效 | 19 |
| 两侧均未恢复 | 53 |

两侧都收到 Sequence 171 和 320，以上统计覆盖明确的观察序列范围 171..320，共 150 个序列。共同恢复为 **76/150 = 50.67%**，由直接匹配得到，不是两侧恢复比例的乘积。这是观察序列范围内的联合有效解码率，不是依据板端 `tx_completed` 计算的无线 PRR。没有将连续发送的序列错误地按 0..149 过滤。

两侧共同恢复的速率为 76/30 = **2.53 个共同有效测试事件/s**，尚未执行控制动作，不能称为联合控制执行吞吐量。

在这一明确范围内，最长连续 BLE 缺失为 7、ZigBee 为 4、未共同恢复为 7、两侧均缺失为 4。未来同步控制的漏收保持、过期和截止时间规则需要覆盖这种连续缺失，不能仅对成功包报告时间误差。

## 实时与完整离线回放核对

同一份双台 ZigBee IQ 使用原参数完整回放，仍为 95 包，逐包 Sequence、完整 PHY 帧与采样位置与实时结果完全一致。

同一份双台 BLE IQ 完整回放，仍为 677 个 PDU、78 个目标 secondary，逐个 PDU 和采样位置与实时结果完全一致。

因此本轮没有发现实时解码额外漏包的证据。回放队列达到 64 是文件背压行为，不是实时溢出。相关摘要为 `assessment_replay_zigbee.summary.json` 和 `assessment_replay_ble.summary.json`。

双台 ZigBee 块处理均值 5.82 ms、P99 9.55 ms、最大 13.27 ms；单块样本时长 8.192 ms。部分处理时长超预算但实时队列最高 3，短时由队列吸收。BLE 均值 5.30 ms、P99 6.93 ms。不能用这些 30 s 数据承诺长时间稳定。

## 同步和 exadv 结论边界

两份双台 IQ 来自两块独立设备，已验证独立接收与完整负载关联。但 `sample_time_s` 起点和采样时钟各自独立，本轮没有共享触发或时间轴校准，不计算两路原始时间戳之差作为同步精度。

现有负载仍为同一性能测试帧，没有新增两侧独立命令、同步字段或实际执行事件。当前仍是固定频率 secondary 接收；严格 primary/AuxPtr 匹配为 0，诊断配对为 62，不能将后者当作完整标准 exadv 跟随成功。

## 下一步

保存本轮 USB 接法、RF 参数和源码散列，保持 700 kHz 配置。再做至少两轮独立实验，使用不同 Run ID，形成至少三轮完整记录；后续补充反向顺序，区分双台活动效应和随时间变化。

同时可开始设计两路采样时间轴的校准；取得校准和误差边界之后，再测同步字段、目标处理时刻和连续漏收保持能力。本轮不需要因 95 比 104/108 少几包就立即重写解调器，也不能因没有掉线就宣布接收可靠性已满足高可靠控制要求。
