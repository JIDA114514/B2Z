# UC1 论文主线实验执行计划

日期：2026-11-19。依据 [AGENTS.md](../../AGENTS.md)、[当前研究范围](../paper/current_research_plan.md)及已接受的 [UC1 协议](../reference/unified_compact_protocol_proposal.md)。状态：实验设计与软件交付计划；UC1/C3 板端已实现并完成本地验证（[接口](../reference/uc1_board_interface.md)），主机接收/分析适配与物理采集尚未完成。本文的参数是先导阶段默认值，确认性矩阵在先导结束后单独冻结。

## 1. 目标、优先级与完成边界

核心问题：单发送机下，同任务及同有效波形预算上限时，共包的负载/分片成本是否转化为联合命令解析收益，哪些条件下不成立？固定 secondary 的时间参考与失更管理作为支撑。

优先完成会改代码的功能及各一次实测，再冻结版本进行重复。本文不恢复最大速率、实际同步执行、微秒级精度、完整跟随在线机制、商用多节点或主动干扰平台目标。历史 N1–N5 不整批重做，UC1 数据不与旧格式合并为同配置重复。

| 阶段 | 工作 | 板端参与 | 出口 |
| --- | --- | --- | --- |
| P0 | 差异论证、协议/时间/基线口径核对 | 无需上板 | 问题—设计—证据对照表，明确不能证明的内容 |
| P1 | UC1/C3 与实验工具实现、本地验证 | 修改并同步源码；用户构建 | 每项软件功能有测试与可生成配置，无虚构 CLI |
| P2 | 共包、分别发送、分片、在线机制桥接初验 | 必须 | 每个正式要用的分支至少一轮实测，问题修复后再冻结 |
| P3 | RF 先导、样本量与确认性配置冻结 | 必须 | 固件/接收/分析版本、任务表、拓扑、矩阵、停止规则冻结 |
| P4 | 主要成本/可靠性与时间支撑重复 | 只改参数，用户运行 | 每主要条件至少 3 轮独立重复，完整失败与统计 |
| P5 | 证据审计与论文结论收敛 | 通常无需 | 可复查图表与适用边界；通过后进入写作 |

P0 可以与 P1 并行推进。前作差异仍不明确时可以完成可逆的原型验证，但不能把大量确认性重复当作新颖性证明。

## 2. 对照组、负载与预算

### 2.1 三组使用同样的 UC1 应用语义

| 代号 | 发射方式 | 接收方式 | 解释边界 |
| --- | --- | --- | --- |
| JC | primary + 共包 secondary | BLE 固定 ch3，IEEE 固定 ch12 | 两侧解码独立，不测跟随 |
| SC | primary + BLE-only secondary + 独立 BlueBee | 同样 BLE ch3 / IEEE ch12 | 与 JC 保持 RF 频点一致，分开记录两侧突发参考 |
| LC | legacy BLE 完整记录或 C3 全分片 + 独立 BlueBee | BLE 固定 ch39，IEEE ch12 | BLE 频点与 JC/SC 不同，可靠性差异不能只归因于格式 |

单发送机串行发送，分片集合和独立 IEEE 构成一次完整逻辑尝试。SC/LC 的 BLE 先发顺序固定并披露；不从这一顺序推导共包同步精度收益。保持两侧目标、opcode、参数、应用 blob、V/E、首次计划时隙、RF 功率与接收设置一致。原始内容按本侧独立解码后校验。

先审查 C3 是否只包含完成独立重组所需信息，公开其 15 B 头的设计理由及旧 C2 成本敏感性。不以历史 C2 的 K=1 成本冒充 UC1 重发基线，也不声称这是理论最优 legacy 编码。RF 条件不同的 LC 比较保留为配置级结果。

### 2.2 主矩阵只选三个代表负载

b/z 是本侧扩展区字节数，不含固定 26 B。所有点满足首阶段工作域。

| 点 | b,z | 两侧记录 B | JC payload B | 作用 |
| --- | --- | --- | ---: | --- |
| A | 0,0 | 26 / 26 | 179 | 短记录，legacy 直接承载，保留可能不占优点 |
| B | 26,0 | 52 / 26 | 205 | BLE 长记录，C3 五片 |
| C | 2,6 | 28 / 32 | 205 | C3 三片，增加 IEEE 数据；与 B 相同 JC 长度 |

另以 b=1,z=0 做直接 legacy 27 B 边界的功能初验，不单独扩大为主重复矩阵。容量报告展示实际工作域和代表点；`b+4z≤76` 仅为 UC1 布局的理论 PDU 预算，未扩展实现前不做最大容量声明。

### 2.3 K=1 成本与同预算策略

下表为设计有效波形预算，非实测 RF 时长。SC 采用 UC1 BLE-only payload `43+b`，故一次成本为 `136+8(53+b)+8(136+4z)`，与 JC 同为 `1648+8b+32z` µs；SC 有三个突发，JC 有两个。生成器必须逐突发核对这些公式。

| 点 | JC/SC µs/完整尝试 | LC µs/完整尝试 | JC/SC/LC 突发数 | Q=6000 µs 时 K（JC/SC/LC） | 未用预算 µs（JC/SC/LC） |
| --- | ---: | ---: | --- | --- | --- |
| A | 1648 | 1456 | 2 / 3 / 2 | 3 / 3 / 4 | 1056 / 1056 / 176 |
| B | 1856 | 2904 | 2 / 3 / 6 | 3 / 3 / 2 | 432 / 432 / 192 |
| C | 1856 | 2344 | 2 / 3 / 4 | 3 / 3 / 2 | 432 / 432 / 1312 |

主策略只有两种：`single`（K=1）、`budget`（K=floor(Q/C)，Q 初始为每任务 6000 µs）。JC/SC 的 K 相等是预期，不能声称共包必然提供更多重发机会。LC 在 A 点可获得更多重复也是必须保留的结果。

本批解析/成本实验**不额外发纯时间更新槽**，未使用的尝试槽静默，接收器在线定时接受策略不作为解析过滤器。这避免同步填充隐藏成本，且与第 7 节连续时间更新实验分开。若截止判定方法确需额外校准/更新广播，须在 P3 前修订统一预算，显式加入 U 并重算 K，不能采集后补记为零成本。

## 3. 软件优先交付清单（P1）

| 交付 | 接收/分析侧 | 板端 | 本地验收 |
| --- | --- | --- | --- |
| UC1 记录 | 新旧版本分派、真实 blob 校验、纯更新时间、布局配置和缺失拒绝 | 两类型编码、固定长度与稳定任务数据 | 独立向量交叉验证、CRC/长度/类型/溢出/历史回放 |
| 任务计划 | 导出同一 manifest、两侧配置及板端十进制命令 | 同任务跨槽重发，固定绝对 V/E，空槽静默 | 偏移重算、编号不复用、超期/越界拒绝；不要直接套用只支持 16 条手工表项的接口 |
| 三封装 | UC1 legacy 直收、C3 重组、SC/LC 独立参考标注 | JC/SC/LC、逐突发计数和长度日志 | 生成波形、C3 12 B 分片、b=0/1/2 边界与上限 |
| 分片资源 | pending/closed 独立容量及预留、任务去重分离 | 可生成不同 slot 的同任务记录 | 乱序/重复/跨尝试混片/冲突/缺片/两种容量耗尽/时间倒退 |
| 统计与归档 | 四类联合结果、首次/累计、未知截止状态、预算/实际尝试、配置一致性检查 | planned/generated/submitted/completed/timeout 计数 | 错 run、错布局、失败任务、零分母；只写本轮输出 |
| 在线桥接 | UC1 进入时间模型/探测/状态机，分片参考不足不误接入 | 纯时间与命令同长度，连续发送 | 同槽不重复更新、新槽可更新时间、定时拒绝与解析分离 |

计数扩展不改变旧性能协议。DMA 主动轮询、超时有界；FreeRTOS 修改同步 SDK 实际目录，由用户构建和上板。主机与板端都要能表示至少本计划 100 个任务、610 个槽（含前置静默）；可用算法生成，不能默默截断任务表。

P1 结束交付：源码版本、测试报告、配置 schema、准确的生成/采集/分析 CLI、板端命令文件和 dry-run 成本表。CLI 未实现前不发布可复制的 UC1 启动命令；旧 `n5_config --uniform-k` 仍生成历史 v1，不能当作本计划入口。

## 4. 公共任务时序与截止口径

### 4.1 首轮默认时序

- 每轮正式默认 N=100 个任务，尝试时隙周期 500 ms，每任务窗口 6 槽（3 s）。前 10 槽静默留启动余量；任务 j 的首次 slot 为 `10+6j`，j=0..99，command_id=j+1。
- 相对首次参考 R0，最迟接受 V=R0+2500 ms，目标软件处理 E=R0+3000 ms。命令实际动作不属于验收。
- 尝试放在窗口前 K 槽，K 最大 4；其余静默。末次计划参考距 V 至少 1 s，但这不是实际空口时限的证明。
- 板端计划约 305 s；接收建议 330 s，先启动双端再启动板端，起止以实际启动与日志核对。前置静默不是时间校准。
- 功能初验缩为 10 任务，RF 先导为 30 任务；各自时长按同一生成器计算，不能改变语义。

primary 到 secondary 偏移、SC 的 IEEE 提交间隔、LC 分片间隔和调谐保护由已有实现核对。生成器检查完整尝试及下一槽 primary 不重叠、全部可在 V 前完成。若 500 ms 不可行，在先导前对所有组统一增大周期和窗口并重新生成，而不是仅给某组额外时间。该实验不是最大速率搜索。

### 4.2 必须同时输出的三个结果层次

1. `first_attempt`：两侧是否各自在第一次完整逻辑尝试有效恢复；C3 必须该尝试全部分片完成。
2. `within_planned_attempts`：在计划 K 个尝试中，两侧是否分别至少恢复一次同任务，允许来自不同槽。它是限定尝试数的解析率，不能自动称截止期内成功。
3. `deadline_class`：各侧按可审计的本地 IQ 时间、参考映射与不确定区间判断 on_time/late/unknown；两侧均 on_time 才计确定的截止前联合成功。已解码但跨边界或参考缺失为 unknown。

P2 必须产出 deadline 方法审计：参考来自哪里、训练/验证是否分离、计划到实际发送的不确定性、LC 最后一片完整记录可用时刻如何映射、丢样如何影响时间轴。不能用待测包自己的 slot 强行对齐来“验证”其准时，也不能以串口/DMA 时刻代替 RF 校准。

若现有设备无法建立可信时间界，继续输出第 1/2 层及 unknown 数；在 P3 冻结前将论文相应结论明确收窄为“限定计划尝试的联合解析”，不得声称严格截止内交付。此决定记录在当前研究计划，不靠新增高精度设备自动扩大范围。定时软件拒绝率另列，不从已解码任务中删除。

## 5. 桥接初验（P2）

使用新 Run ID，阶段与条件由 manifest 分配；下表 H 编号不是设备 run_id，也不预占旧 N5 的 2521–2529。

| 初验 | 配置与操作 | 必须核对 |
| --- | --- | --- |
| H1 | 生成 IQ 上 A/B/C 三布局独立双解码，再选两个布局同一实录 IQ 验证 | 400+8b 的标记差候选公式与实际标记定义/符号，CRC与内容；同 IQ不作为双端实测 |
| H2 | 稳定链路，A/B/C × JC/SC/LC，每点 10 任务，K=1 | 两侧完整解析、包长、分片数、各突发计数、逐尝试成本；共 9 个短配置 |
| H3 | LC b=1,z=0，10 任务 | 27 B 直接记录，不应进入分片 |
| H4 | A × LC 用 K=4；B × JC/SC/LC 各用预算 K | 截止时刻不随重发移动、blob不变、新 slot 独立重组、任务不重复处理；4 个短配置 |
| H5 | JC，固定 B 长度，正常/仅 BLE 失更/仅 IEEE 失更，各一轮 | 纯时间填充保持位置、在线状态、留出探测和重获；参照第 7 节 |
| H6 | 已存本轮数据上注入错布局、坏CRC、跨 slot 混片和资源耗尽 | 明确标为回放/合成；接收异常不得产生虚假任务与时间更新 |

H2 不要求先取得 100% 无线成功；需要已恢复样本完整正确、所有丢失保留、无法归因问题不掩盖。但某分支始终无有效解析、预算不符或处理崩溃时，该分支未通过。修复后新 Run ID 初验，不覆盖失败记录。

## 6. RF 先导与核心重复（P3/P4）

### 6.1 只冻结两个 RF 条件

- R0：已有可审计稳定接线或稳定天线条件，用于正确性和成本基准。不默认存在额外分配/衰减附件，沿用实际可用且已验证的连接。
- R1：固定天线布局下存在部分解码缺失的条件。保存距离、朝向、位置照片/示意、功率与两端增益；正式轮次中不手动改变条件、不临时制造断连。

先用 B 点进行最多两组候选布局的先导，每组 JC/SC/LC 各 30 任务；每组跨两个独立录制块观察稳定性（最多 12 个短 run）。选取规则是存在可观测缺失且非持续全失、采集质量可用，不根据哪种格式“赢得更多”选条件。保留所有候选结果。若全部全收或全失，结束先导并修改下一批设计，不无限调参至得到期待收益。

每组三个模式尽量相邻执行，全部使用同一布局；不能分别给三组寻找“最佳”接收条件。LC 信道差异单列。USB/主机丢样、RF 饱和等质量问题先处理，不能一概归因于无线丢包。

### 6.2 确认性矩阵上限与执行顺序

默认矩阵如下，先导结束后允许按样本精度调整 N 或重复数，必须在正式数据产生前冻结。先导不能事后变成确认性重复。

| RF | 负载 | 策略 | 模式 | 独立重复 | run 数 |
| --- | --- | --- | --- | ---: | ---: |
| R0 | A/B/C | single | JC/SC/LC | 3 | 27 |
| R1 | A/B/C | single 与 budget | JC/SC/LC | 3 | 54 |
| 合计 | | | | | 81 |

默认每 run 100 任务，合计 8100 计划任务；按 330 s 接收窗口约 7.4 小时纯采集，另加准备、复核和重启。此为排期估算，不是达到显著性的样本量保证。R0 不做全套预算重复；重复的收益重点放在 R1，避免矩阵翻倍。

R0 每负载的三个区组采用 JC→SC→LC、SC→LC→JC、LC→JC→SC。R1 每负载将六个条件记为 J1/S1/L1/JQ/SQ/LQ，冻结次序为：

```text
区组1：J1 S1 L1 JQ SQ LQ
区组2：LQ SQ JQ L1 S1 J1
区组3：L1 JQ SQ LQ J1 S1
```

负载顺序在三个区组采用 A/B/C、B/C/A、C/A/B，尽可能跨不同时间段；每个 run 都重新启动收发，不把一条长录制切三段充当重复。记录开始时间，区组差异大时报告漂移，三组不能完全消除所有顺序效应。

各 run 保存完整双侧逐包/事件与板端日志。P2 关键布局/失败点及 P4 每主要配置至少一轮保存双侧 IQ；其余 IQ 保留策略在采集前固定，不能只保存成功片段。估算数据量与磁盘余量后安排分批采集，不自动清理旧 IQ。

## 7. 时间参考支撑的有限实验

仅 JC，固定 B 布局，让非零 b 的补偿与填充得到实测。沿用 N5 的训练/留出原则和明确阈值，但配置生成必须输出 UC1；不直接复用旧 v1 二进制。

建议每轮 300 槽、500 ms、150 s 板端计划、180 s 接收：正常、BLE 单侧失更、IEEE 单侧失更三种条件。每种先 H5 一轮初验；冻结后每种 3 轮，共 9 个正式 run。核心成本/可靠性与时间支撑合计默认 90 个正式 run，纯采集约 7.9 小时。

参考任务首次槽为 70、90、150、190、240、270，各 K=3；V=首次参考+2000 ms、E=首次参考+3000 ms。剩余槽发等长纯时间更新，共 18 个命令尝试、282 个更新时间槽。每轮全部 300 次成本照计，不能只统计六任务。固定留出探测使用不与尝试冲突的 `[69,79,...,299]`，所有合法输入依原规则划分训练/验证。

单侧干预安排在先确认 tracking 后、约 55–80 s 的预登记窗口内，时长必须超过冻结 stale 阈值且留足恢复段；只改变目标侧接收条件。终端提示和人工记录用于操作，实际证据由最后有效接收、stale 事件、恢复后的首包及状态转换给出。人工误差保留，未达到 stale 的轮次标为干预未覆盖，不冒充成功；补采用新 run，原数据保留。

输出每侧状态时长、更新年龄、探测覆盖、留出预测残差、缺失与恢复事件；仅在有可判定事件时计算恢复所需样本数/本侧 IQ 时间。无丢样时间轴不足时标未知，不使用两个进程墙钟计算恢复同步精度。原 N5 回放消融可作历史支撑，仅对 UC1 变更影响的规则做回归，不再追加整个新消融矩阵。

## 8. 统计、停止与证据输出

- 每任务输出 planned_attempts、两侧各次结果、首次成功槽、联合四分类、两侧在不同槽成功的累计结果、deadline 状态、命令/任务拒绝原因。缺失整任务仍留在分母。
- 成本输出计划/生成/提交/DMA 完成的逐突发字节与波形预算、更新成本、未用预算；实际 RF 发射未校准时明确为代理。单位成功任务成本为全部相关提交波形预算/联合解析数，零成功 N/A；同步给出计划与完成代理口径。
- 各轮和配对区组分别报告联合解析率及差值。主要比较 JC–SC 与 JC–LC，K 增益作组内支撑；不把两侧成功率相乘。
- 置信区间方法在 P3 冻结，优先考虑独立区组/轮与连续任务块的相关性。仅三轮时给出全部轮次、范围及带限制的区组区间，不用数千包伪造独立样本数；精度不足则按预定整区组追加或减弱结论，不逐轮看显著性决定停。
- 同 IQ 位置偏移、独立双端解析、离线注入、DMA 代理与未知 deadline 分栏。时间残差报告中位数、P95、P99、最大值及样本量，样本不足时不解释尾部分位稳定性。
- 模式/配置不符、崩溃、截断等 run 保留并标原因；预先定义哪些不进入 RF 因果比较，资源拒绝与无线失败不得因结果不好而删除。软件修复影响生成/解码/统计时重新冻结受影响版本和条件，不混合为同一重复组。
- 正式矩阵完成即汇总，包括不占优或无差异。若所有 R1 任务仍全收，报告在该条件未辨识收益；不在正式阶段边采边调 RF。
