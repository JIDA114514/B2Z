# 连续单包双协议粗粒度同步与简单控制：下一阶段计划

更新日期：2026-11-13。本计划依据现有实验重排后续工作，替代原 P0–P5 的待办状态。当前重点是补齐公平对照、独立时间评价和最终跨信道配置下的完整证据，再对选定的主要配置增加重复。已有功能、观察结果和未验证主张分别列明。

## 1. 研究目标与证据边界

研究目标是在连续广播的每个事件中，仅使用一个 secondary `AUX_ADV_IND`，让 BLE 与 BlueBee/IEEE 802.15.4 两条独立接收链恢复各自命令及共同时间语义，研究其控制成本、相对时间保持与粗粒度软件调度效果。允许重复同一任务；多个 secondary 或链式 PDU 不能合称为一个包，成本计入 primary、secondary、失败尝试和所有重发。

两侧独立完成 PHY、应用校验和本侧命令恢复后，才按 `(run_id, command_id)` 汇总任务，按 `slot_index` 汇总物理尝试。不能借另一侧已恢复的字段重构本侧结果。旧 `B2 5A` 性能协议及 Sequence 规则保持兼容；当前共包采用独立的 `B2 43` v1 格式，字段及预算见[v1 负载草案](control_sync_packet_v1_draft.md)。

论文结论随测量能力确定：若要声称两类接收端达到给定同步精度，需要独立于被评估时间模型、具有明确误差界的共同参考及被测事件。无法建立该参考时，结论限定为共包时间信息分发、相对时间保持与软件调度原型。拟合残差、主机回调差值和人为输入的参考误差界不能替代实测跨设备同步误差。50 ms 可作为预先选定的粗粒度候选容差，并报告 10/100 ms 敏感性；这些不是已测得精度。

现有设备为一块发送 SDR、两块 HackRF 和主机。商用协议栈、物理执行器、共享时钟/触发附件及更多独立节点不视为已有条件；这些验证作为后续扩展。BlueBee 已有双协议广播和控制先例，exadv 共包的创新性仍需结合[先例研究](sync_control_payload_research.md)继续查新，不能仅以协议升级、字段增加或负载变大宣称贡献。

### 当前设备下的验收范围

本轮计划不要求新增逻辑分析仪、示波器、共享时钟、硬件触发或执行器。现有硬件下必须完成的是可复查的功能、成本核算、软件取时、固定频点 IQ 相对预测和真实接收缺失诊断。不能测得的绝对量列为未测，不以假设数值填补，也不作为进入后续阶段的前置门槛。

| 内容 | 当前可完成的测量 | 保留的限制 |
| --- | --- | --- |
| 跨信道发射的时间保持 | BLE 固定 ch3、IEEE 固定 ch12 独立连续 IQ；用本侧样本及留出包评价相对预测 | 不证明实际跟随模式的采样连续性、绝对同步或真实执行时差 |
| 实际 BLE 跟随 | 逐槽阶段、主机软件耗时、解析与关联；增加状态和流连续性诊断 | 若无法界定切频丢样/间隙，跟随时间精度为未测；不把回调时差称为 RF 间隔 |
| 真实单侧漏收 | 两侧独立有效记录、因果状态转换、恢复所需包数；具备本侧可信采样进度时评价在线预测 | 缺失期间误差不可观测；无参考界时调度拒绝属于可验证行为，执行精度不作验收 |
| 板端延迟归因 | DMA 准备/提交/返回软件时间和逐槽分布，与接收结果关联 | 不直接测量真实 RF 起点；相关性和软件阶段定位不等于唯一物理根因 |
| 控制成本 | 根据实际提交的波形长度、重复与失败清单核算，明确 padding | 实际 RF 发射占用/能耗无测量时不声称已实测 |

硬件校准可作为以后提升结论范围的扩展；当前论文主张应随上述可观测量收敛。

1901–1906 的相关单任务记录报告 `auxptr_dma_window_miss=10/10`，2001 为 `120/120`。目前 primary 时间标记在 DMA 调用前，secondary 标记在 DMA 调用返回后，两者不是相同阶段的取时。该软件代理计数不能直接证明空口窗口越界，也不能被直接认定为纯记录延迟；需按 N3 拆分准备、提交和返回取时。

## 3. 下一阶段工作包与顺序

按 N1→N2→N3→N4/N5 推进；N3 的取时诊断可与前两项并行。对每个工作包先完成实现与一轮可审计验证，再选择主要配置做独立重复。增加已有实验的次数不能替代下列交付物。

### N1：最终跨信道配置的双端多任务实验

具体任务清单、接收接口前置工作和可复制指令见 [N1 执行方案](n1_cross_channel_experiment_plan.md)；首轮采用 Run 2001、500 ms 周期、120 槽和三项逻辑任务。

目的：在同一轮同时验证 BLE 实际跟随、IEEE 独立接收、连续时间更新和多命令解析，连接目前分散的功能证据。

- 发送端使用 `rf_mode=standard_secondary_ch3`，primary ch39、secondary BLE ch3 / IEEE ch12。复用 1801 的连续更新时间及多任务语义，按当前跨信道发送能力调整周期、槽位、有效期和执行提前量，显式记录实际参数。
- HackRF A 按 AuxPtr 从 ch39 跟随至 ch3；HackRF B 固定 IEEE ch12。两侧记录同轮 `run_id`、时隙与命令，不将 1905 的双 BLE 接收配置当作双协议实验。
- 跟随验证器已支持多任务记录，`plan_analyze.py --ble-flow` 已接入逐任务汇总所需的本侧事件；本轮使用更新后的脚本保存 CRC 证据和采集起止时间。当前跟随验证器的解析成功不自动表示已经调用实时控制调度器；报告区分解码、接受、调度和软件处理。
- 输出逐槽四象限、缺失 DID、primary 检出数、成功跟随数/计划数、成功跟随数/有效 primary 数、各任务两侧字段和联合解析率。记录迟到、过期、重复及时间质量拒绝原因。
- 保存完整板端日志与两侧逐事件数据；IEEE 保存 IQ。若增加跟随 IQ 保存，必须附切频状态和采样连续性诊断，不能默认当前跟随脚本已有 IQ。

验收交付：同轮跨信道双协议多任务报告及 CSV/JSON；失败任务保留在分母中。功能样例与可靠性统计分开，不要求用一次偶然的 100% 结果掩盖失败。若仍缺少校准参考，软件调度拒绝应如实记录。

#### N1 补充交付：follow 失败的阶段分解

首轮功能通过后，仍需为 N2 公平比较和 N5 漏收实验补充诊断观测，不将全部失败归为无线丢包。

- 逐计划槽记录发射端生成/提交/完成，接收端 primary 候选/CRC/字段校验、主机排队、切频请求/返回、secondary 窗口进入/退出、候选/CRC/应用校验、身份匹配和最终跟随。未进入的阶段记为未到达，无法观测的阶段记为未知。
- 报告各阶段计数、条件分母和全计划分母，以及互斥的最终失败分类。2001 当前只能分为 18/120 primary 未检出、9/120 已解出 primary 后 secondary 未解出、93/120 配对成功；这三个类别总和为 120，并非物理根因。
- 主机切频耗时、队列延迟、流进度和设备实际调谐返回状态用于诊断；主机时刻不能证明 RF 在 AuxPtr 空口窗口内已可接收。没有候选不能认定“无 RF 信号”，CRC 失败为零不能认定链路无误码。
- 对失败槽保留有信道状态标记的 IQ 片段及解调候选诊断，核查切频丢样/间隙和处理积压。当前跟随脚本尚缺这类完整记录，须作为软件前置项实现。
- 两块接收机正常承担 BLE/IEEE 验证；需要另一块固定 BLE ch3 辅助诊断时另开诊断轮，并明确该轮不再是独立双协议验证。没有额外设备或共同时间基准时，不要求伪造同轮全链 RF 根因。

验收交付：逐槽阶段表、阶段转移统计、失败案例与“原因未定”列表。阶段归类可以使用已有 2001；根因判断需要新增可区分假设的证据。

### N2：分别发送基线与控制效率

具体对照、字节预算、首轮任务及实现前置项见 [N2 实验方案](n2_separate_transmission_experiment_plan.md)。N2 软件已实现：`rf_mode=2` 分别发送、BLE-only 严格格式校验、逐突发日志/成本、双端联合与跨轮比较；2101–2103 已完成首轮功能与成本初验：固定接收两组均 120/120、任务 3/3；2103 跟随 75/120、任务 3/3，未达到全槽跟随验收。功率配置未知、重复确认及同步精度仍待补充。当前进入 N2 的依据为 Run 2001 的 N1 首轮三任务联合解析 3/3；可靠性重复及同步精度仍待完成。

目的：检验共包是否带来可测收益，以及收益对应的条件和代价。

1. 实现基线 A：同一发送设备分别发送 BLE 与 IEEE 802.15.4 对应任务，说明顺序发送、波形和硬件能力。不能默认额外发射机或并行发送。
2. 沿用基线 B：同包解码后立即软件处理。其功能回放已完成，后续补效果比较，统一任务、有效期及后验截止时间评价规则；不要求无时间模型的基线假装具备在线全局时间判断。
3. 实验组 C：同包携带两侧控制与时间信息，使用时间模型；参考未校准时，仅比较可直接测得的解析、成本和本侧软件指标，跨机同步指标记为未测。

对照保持相同应用语义、目标数、射频条件、截止时间和明确的重发策略。分别比较同空口预算下的联合成功率，以及达到同一可靠性目标时的成本；未达到目标的配置也保留。不同模式的格式、发送顺序和硬件差异列入配置表。

交付指标：联合有效解析任务数/计划任务数、截止时间内结果、全部 RF 发射时长/成功联合任务数、物理发送次数、请求至软件完成时延和可持续任务速率。时延必须明确请求与完成事件、时间域和校准条件；无法对齐时不报告跨机完成时延。RF 成本包含 primary、secondary、时间更新、失败尝试和重发，包间静默单列。BlueBee 编码膨胀及重复同步字段计入预算，不预设共包一定更省时或更可靠。

### N3：板端时间参考与独立同步评价

详细的软件前置项、采集矩阵、现有可用命令、预登记训练/探测规则和验收边界见 [N3 实验方案](n3_time_reference_experiment_plan.md)。板端取时、主机因果时间保持与诊断解析已完成本地实现；2101/2103 已作探索性复核，接下来构建上板并采集 2201 跨信道固定频点双端记录；不得将现有 DMA 括号直接当作实际 RF 时间。

目的：区分记录延迟、DMA 准备延迟和实际空口偏差，并决定论文能报告哪一层同步结论。

- 在 primary、secondary 相同代码位置记录 DMA 调用前、提交寄存器写入前后、调用返回后的时刻，单列缓存刷新和准备耗时；必要时检查将准备移至目标等待之前的可行性。继续使用寄存器轮询与明确超时，不依赖 DMA IRQ。
- 区分提交前已错过窗口与返回后代理值越界，不将 DMA 提交、返回、完成混称为空口发射。统一空口参考点和包内 BLE/IEEE 位置差后再解释 AuxPtr 与同步字段。
- 核查 IQ 能覆盖的时间基准：1905 仅保存 ch3 IQ，1906 跟随记录未保存 IQ，不能据此测 primary→secondary 空口间隔。两台独立 HackRF 的 IQ 起点也不能直接相减；单机切频 IQ 只有在采样连续性及间隙误差得到验证后才可用于相应时间估计。
- 参考基准独立于被评估模型，校准段与验证段预先分开；不得用验证包逐包对齐两路 IQ 后将残差当作同步算法结果。单列采集零点、采样率、固定延迟及板端参考不确定度。
- 有可审计共同参考时，比较立即处理与时间模型处理的目标时刻偏差和两侧软件事件时差，报告偏差、中位数、P95、P99、最大值、CDF、有效样本和缺失数。主容差及敏感性容差在实验前固定，达标任务数以全部计划任务为分母。

验收交付：取时定义、误差预算和独立验证报告。若无法建立误差界，则将论文同步结论限定为相对时间保持和软件调度原型；假设参考界的功能回放明确标注，不作为实测精度。物理执行器动作不属于当前设备可直接验证的事件。

#### N3-A：跨信道时间保持与跟随观测边界（必做）

1703–1705 仅作为同频诊断参考，不能直接推广到跨信道发射与 BLE 跟随接收。第一层为当前设备必须完成的时间保持实验；第二层必须完成观测能力核查，精度评价以采样连续性可核验为条件，不要求新增硬件：

1. **跨信道发射、固定频点接收**：板端仍发 ch39 primary/ch3 secondary，两块 HackRF 分别固定 BLE ch3、IEEE ch12，记录连续 IQ；按预登记训练/验证集复核不同有效包数、训练跨度、更新间隔和失更年龄下的预测残差。这验证最终发送配置下的时间保持，单独标注没有 BLE 跟随接收。
2. **实际跟随接收**：在 BLE 接收链具备可信采样进度、切频间隙记录和本侧在线模型后，再测试跟随模式下的时间保持。若采样连续性与误差无法说明，保留功能/恢复记录，不能用 host callback 时刻替代 IQ 时间轴；不宣称已完成最终接收配置的时间保持精度验证。

现有 holdover_analyze.py 固定 300 槽、200 ms 且针对纯时间更新；需先支持显式周期、时隙清单和混合任务，并核对训练包实际可用时刻。主验证记录只用于评分，先用此前可用记录作预测，再记录残差，禁止用同一个验证包先更新再评分。比较同频/跨信道影响时采用相同周期和训练跨度；旧 200 ms 与新 500 ms 的结果仅作配置间描述，不能把差异全部归因于切频。

输出单侧有符号预测残差、双侧共同验证包上的相对估计差、更新年龄、训练跨度/包数、模型速率及缺失数，报告中位数/P95/P99/最大值/CDF。共同验证包只用于后验评价，不允许重构另一侧负载或逐包对齐。没有共同 RF 参考时仍只称相对预测/保持结果。

#### N3-B：逐槽发送延迟与 holdover 残差归因（必做）

以 (run_id, slot_index) 连接完整板端逐槽日志和两侧残差，导出 secondary_dma_late_us、auxptr_dma_delta_us、切频耗时、生成/缓存刷新/提交阶段耗时、包间隔偏差、检测质量、丢样告警及模型训练集。缺失字段保持缺失，不以最终平均值回填每槽。

分别统计各时延的有符号分布与相邻槽差值，报告样本数、最小值、中位数、P95/P99、最大值、随时间轨迹；固定偏置与抖动分开。对单侧残差、双侧相对差、冻结/周期更新模型分别分析关联，注明共同发送抖动可能在双侧差值中抵消。晚发影响训练斜率或单侧预测，不能仅凭双侧差较小就认定发射稳定。

相关分析仅用于提出解释。需用匹配周期的同频/跨信道配置、固定/跟随接收、准备工作提前与否等单因素对照区分发送抖动、时钟偏差和采集异常。不得逐验证槽减去待测 late_us 后把结果作为在线同步精度；若设计发送补偿算法，必须因果可用，并在独立验证段评价。

2001 现有逐槽 secondary_dma_late_us 的中位数为 80736 µs、P95 为 80946.2 µs、最大值为 81514 µs（120 槽、线性分位数）。其中最大值出现在跟随成功槽；9 个跟随失败槽的中位数为 80559 µs，不能据此认定 late_us 较大导致失败。该轮缺少 BLE 样本时间与 holdover 残差，因此目前只能关联板端代理时延和跟随结果，不能完成残差归因。

### N4：容量、legacy 对照与适用范围

N4 容量扫描及两层对照已取得首轮结果，见 [N4 两层结果报告](n4_two_layer_results.md)和 [N4 实验方案](n4_capacity_experiment_plan.md)。两层各条件均为单轮，等预算重发对照仍待完成；不能据此关闭可靠性重复要求。2204同轮IEEE记录缺项按用户决定移至后续补采和独立重复阶段，不宣称N3完整双端验收完成。

目的：说明 exadv 单包容量解决的具体任务约束，以及负载增长何时导致失败。

- 基于当前 224 B PDU payload 工作点，逐项核算扩展头、AD 封装、35 B BLE 记录、IEEE 原始记录、映射区域、同步和校验开销；单个 PDU payload 不超过 255 B。旧性能协议的 46 B 上限不直接作为共包容量。
- 先定义可变负载的版本与校验方式，再扫描 BLE/IEEE 控制长度组合，覆盖短负载、当前工作点和接近容量边界的组合。输出字节预算、两侧及联合有效解析率、容量边界和联合成功率热力图。
- legacy 对照保持应用任务与时间语义相同，允许合理紧凑编码或分包并计入全部成本；不能仅因当前 v1 固定字段长于 legacy 容量，就判定其无法承载同任务。确实不可实现时列出具体约束，不虚构测量值。

验收交付：格式预算表、实测容量结果和可复查的对照条件，说明容量增加与可靠性、空口成本之间的关系。

### N5：机制消融、失败行为与任务结果

当前详细执行依据为 [N5 实验方案](n5_mechanism_experiment_plan.md)。先补齐 v1 在线失更/重获、独立探测留出及配置生成接口，再执行 2501–2503；现有板端 plan 命令可复用。N4 v2/C1 解析功能不等于在线定时语义已适配。

目的：确定收益来自哪些机制，以及失更、漏收和处理延迟如何影响任务。

- 复用 1703–1705 的方法，分别改变有效历史包数、训练跨度、更新间隔和连续失更长度；补充固定偏移、一次估频后冻结、周期更新等对照。保持验证集独立，避免只比较参与拟合的包。
- 改变命令重复次数 K、执行提前量和任务负载，记录联合解析、接受/拒绝、去重、过期、迟到、失去时间质量及任务成本。单侧漏收仍计入计划任务分母。
- 检查错误目标、未知命令、冲突字段、重复与乱序等行为，将已有单元测试、同 IQ 回放、注入掩码及真实空口观测分别列出。离线漂移或丢包注入只能作为仿真/回放证据。
- 有独立时间参考后才计算同步达标率；没有时仅报告相对预测误差及本侧软件事件，不能将接受或解析计数替代同步成功。

#### N5 补充交付：真实单侧漏收后的在线观测与恢复（必做）

保留离线掩码作为可控消融，同时增加现场真实解码缺失与因果在线处理的证据。2001 已有 IEEE-only 27/120 槽，但它没有 BLE 在线保持/恢复模型，不能称为真实失更后的同步成功率。

先在有连续 IQ 采样进度的固定频点双接收链上接入并验证本侧在线时间模型，板端保持跨信道发送；分别记录自然出现的 BLE-only/IEEE-only 缺失。实际跟随链先补齐阶段/失更/恢复状态记录，只有其采样连续性可核验时才扩展在线时间预测。两种接收配置的结论分别报告。若自然条件不足以覆盖另一方向，可在已具备的接线/接收条件内仅改变一侧条件，记录实际方法与参数；不默认已有衰减器或干扰源。软件屏蔽观测、暂停扫描和事后掩码分别标为协议层失更、扫描不可用或离线注入，不冒充 RF 损坏。

预先确定短/中/长失更观察区间，保存各侧有效包、状态转换、时钟更新、最近更新时间、错误界/拒绝判据和命令生命周期。对每段缺失报告持续时间、缺失槽数、是否仍能解析任务、恢复所需有效包数和时间，以及恢复后的未参与更新的验证包残差。记录时要区分包真实可用时间与事后解码结果，离线重放真实丢包轨迹仍标为回放，不能标成现场在线结果。

缺失期间没有本侧观测时，不填造逐时刻真实误差；使用恢复后独立探测点或误差有界的外部参考评分，并给出条件样本、未覆盖区间和缺失数。无校准参考时仅报告解析、失更检测、保守拒绝和重获时间参考；同步/执行达标仍为未测。以已有设备完成真实缺失、在线失更/重获及保守拒绝的验证即可满足本项功能交付，不要求硬件测量执行动作。另报所有计划任务的联合解析率及失败数，不能只评价恢复成功的片段。

验收交付：参数—效果—成本曲线与失败案例表。先做少量有解释力的配置，避免同时修改多项参数而无法归因。

## 4. 统一归档与统计要求

每轮保存完整板端命令和逐槽统计、代码/固件版本、两侧设备与 RF/USB 配置、独立逐包及逐任务记录、时间参考定义、处理异常、CSV/JSON 和关键 IQ。沿用 `python/experiments/YYYYMMDD_run<run_id>/`；人工观察写入 `notes.md`，联合分析放入 `analyses/`。输入 IQ 的重复分析不增加独立实验轮数。

所有比率给出分子/分母，零分母为 `N/A`。逐槽报告双方成功、仅 BLE、仅 IEEE、双方失败；逐任务按命令去重，另报一次发送、重复 K 次和截止时间内结果。条件误差分布须附全部计划任务数、失败和缺失数，不能只保留成功子集。

主要配置至少三轮独立重复，交替对照顺序，报告逐轮结果、样本数与置信区间；相关连续丢包不无说明地当作独立样本。1703–1705 的既有重复仍有效，但不能代替新跨信道配置或新基线的重复。检查饱和、USB/主机丢样、队列积压及截断；无告警不等于已证明连续无丢样，无法归因的失败标为原因未定。

## 5. 最近一个可执行动作

N2阶段所有必须实验都执行了一次，确认以下四点：
1. 分别发送基线已实际跑通。
   同一 SDR 顺序发送 BLE-only secondary 和独立 BlueBee 波形，两条接收链能恢复各自任务，已有可与共包比较的实测基线。
2. 共包的当前收益得到明确界定。
   在 2101/2102 相同任务下，共包将突发和 DMA 提交次数从 360 降到 240，减少 33.3%，两组任务均为 3/3 有效解析。有效波形总时长相等，因此目前支持“减少发送操作”，不支持“有效空口时长减少三分之一”或能耗下降的结论。跨轮比较报告 (python/experiments/n2_comparison_2101_2102/comparison.md)
3. BLE-only 格式具备实际跟随功能，但跟随可靠性仍有缺口。
   2103 有效 primary 为 88/120，随后成功跟随 secondary 为 75/88，约 85.2%。45 个缺失槽可以分为：32 个未取得有效 primary、13 个取得 primary 后未成功跟随。原因仍不能全部归为无线丢包。
   incomplete_follow_observation 和 verification_passed=false 表示未达到全槽完整验收，不否定已复核的 75 次成功跟随和三项任务成功解析。
4. 软件处理与同步结论的边界得到验证。
   2101 两侧 immediate 各处理三项任务、去重六次；scheduled 因参考质量不足拒绝命令，符合预期。这证明了软件规则有效，尚未证明同步执行收益。

N4 首轮容量扫描与两层对照已完成，结果见 [汇总报告](n4_two_layer_results.md)：第一层相同格式的有效波形成本相等而共包减少突发；第二层紧凑格式的成本收益依负载而变，不能宣称所有负载均更省。

当前推进 [N5 详细方案](n5_mechanism_experiment_plan.md)：先实现主机在线失更/重获、预登记探测留出及分析接口，再进行2501基准、2502 BLE侧缺失、2503 IEEE侧缺失。主实验沿用v1跨信道发送、双端固定频点接收；未知参考界下保留严格定时拒绝，不新增板端命令。2204同轮IEEE补采、N4等预算重发对照及主要配置独立重复仍待完成；若论文将C1与在线调度作为统一方案，还需C1时间语义适配和桥接验证。

当前阶段的完成条件是：有同轮最终配置的双协议功能证据，有公平基线的实际收益或代价结果，有与测量能力一致的时间结论，以及容量/机制/失败边界。商用芯片、执行器和多节点扩展不作为现有设备下必须完成的前置项。裸机构建与上板由用户执行；`app_FreeRTOS/` 的源码修改须同步到 SDK 实际编译目录后再验证。
