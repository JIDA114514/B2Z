# 基于 Run 10265 / 10266 IQ 的继续优化必要性评估

## 结论

存在少量软件可恢复空间，但不建议继续把同步门限、窗口和滤波参数微调作为下一阶段主线。现有数据更支持先做受控 RF 链路与突发叠加信号排查，再决定是否投入完整接收机重构。当前不能断言硬件 IQ 已完全不可恢复，也不能仅凭接收 IQ 证明所有 DMA 提交正常。

## 同一 IQ 的连续回放

两份 IQ 均为 40 s、8 Msps、ch39、相同增益，当前默认内部解调率为 2 Msps。诊断进程改为 4 Msps 后完整连续回放，原记录和默认代码配置没有被覆盖：

| 数据 | 原有效目标包 | 完整 4 Msps 回放 | 新增 Sequence | 丢失原有 Sequence |
|---|---:|---:|---|---|
| 30 B，Run 10265 | 91 | 92 | 128 | 无 |
| 40 B，Run 10266 | 61 | 65 | 64、98、142、146 | 无 |

全部新增包及其余有效目标包均通过 BLE CRC，事后独立复核 Run ID、测试头、确定性填充和 ZigBee FCS。按“30 s / 200 ms / 150 个计划时隙”条件计算，30 B 从 60.67% 到 61.33%，40 B 从 40.67% 到 43.33%；这不是已合并板端完成计数的无线 PRR。

对每个预测时隙的 12 ms 片段，还比较了 2/4 Msps、700/850 kHz 低通、基于目标已观测频偏的显式 60 kHz 数字频移、基于未知接收数据分位数的两电平阈值估计。没有发现能大幅恢复缺失包的配置。显式固定频移只是离线探针，不是已实现的通用自动 CFO 跟踪。片段 DC 状态和抽取起点会变化，正式收益以连续回放结果为准，不能把各片段最佳结果直接称为可部署接收率。

## 缺失时隙到底发生了什么

以 150 个计划时隙为分析条件，在缺失时隙附近取片段，对与目标固定包头兼容的 CRC 失败候选做事后错误统计：

| 分类 | 30 B：59 个缺失时隙 | 40 B：89 个缺失时隙 |
|---|---:|---:|
| 候选相对期望码流 1–2 bit 错误 | 0 | 1 |
| 3–16 bit 错误 | 2 | 7 |
| 超过 16 bit 错误 | 39 | 52 |
| 未找到该类包头兼容候选 | 18 | 29 |

期望 PDU 构造模型已与全部原始 CRC 有效 PDU 逐字节验证一致。已知 Run ID、Sequence 和填充只用于事后错误计数，没有用于接收解码、CRC 修补或候选选择。无兼容候选不等于板端没有发射；片段初始化也可能改变检测结果。

这表明多数剩余失败不是仅差一两位、稍调阈值即可恢复的情形，但不能单凭较多硬判决错误证明原始 IQ 信息不可恢复。

## 能量突增与错误位置

使用通道内 IQ 功率按 100 us 分箱，将超过本包分箱中位数两倍（约 3 dB）的区间定义为突增区间。有效包用实际解码时刻定位，缺失包优先使用对应 primary 的时刻加已测偏移，没有 primary 时使用序列网格；后者具有时序估计不确定性。这些是未校准能量比，不是 RSSI/SNR。

| 指标 | 30 B | 40 B |
|---|---:|---:|
| 缺失时隙中出现 >3 dB 包内峰值突增 | 51/59 | 70/89 |
| 已正确接收包中出现同类突增 | 0/91 | 0/61 |
| 包头兼容 CRC 失败候选内，错误位落在突增区间的比例 | 5223/6257=83.47% | 7582/8058=94.09% |
| 这些候选中突增分箱占时长的平均比例 | 约 22.6% | 约 18.8% |

错误明显集中在包内突发能量升高的区间，支持将突发干扰/叠加信号作为优先排查方向；没有据此识别具体发射源，更不能直接断言一定是 Wi-Fi。板端波形异常和接收前端失真仍需要受控实验排除。

## 代价

对 40 B IQ 的前 10 s 做单进程、顺序核心解码基准（不含 JSON 写出及事件匹配）：

- 2 Msps：墙钟 6.351 s，块平均/P99 5.181/6.335 ms。
- 4 Msps：墙钟 9.504 s，块平均/P99 7.762/9.748 ms。

核心处理成本增加约 49.7%，而完整 40 s 数据仅多恢复 1/4 个包。每块 IQ 对应 8.192 ms，4 Msps 的 P99 已超过该跨度，额外 I/O 和主机竞争还会压缩实时余量。该单次基准不是所有主机的性能保证，但不足以支持直接把 4 Msps 设为默认。

## 建议的下一步

1. 保留当前默认接收链及可审查的 CRC 失败统计；4 Msps 仅作为诊断对照，不继续无界扫描小参数。
2. 先在固定、可控的距离/天线/RF 配置下改善目标相对其他信号的强度，并减少实验环境中可控的其他发射活动；同步观察能量突增是否减少、接收率是否提高。不能仅靠增加 RX 增益假定改善信干比。
3. 保存完整板端命令和最终计数，区分生成/DMA 未完成与接收损失。当前报告的分母仍是有条件的计划时隙数。
4. 若较干净的链路能够达到目标，冻结接收基线并推进共包控制与同步实验；若没有能量突增时仍大量解码失败，再针对定时恢复、频偏跟踪和调制模型做结构性接收机优化。
