# 连续单包双协议粗粒度同步与简单控制：下一阶段计划

更新日期：2026-11-10。本计划依据现有实验重排后续工作，替代原 P0–P5 的待办状态。当前重点是补齐公平对照、独立时间评价和最终跨信道配置下的完整证据，再对选定的主要配置增加重复。已有功能、观察结果和未验证主张分别列明。

## 1. 研究目标与证据边界

研究目标是在连续广播的每个事件中，仅使用一个 secondary `AUX_ADV_IND`，让 BLE 与 BlueBee/IEEE 802.15.4 两条独立接收链恢复各自命令及共同时间语义，研究其控制成本、相对时间保持与粗粒度软件调度效果。允许重复同一任务；多个 secondary 或链式 PDU 不能合称为一个包，成本计入 primary、secondary、失败尝试和所有重发。

两侧独立完成 PHY、应用校验和本侧命令恢复后，才按 `(run_id, command_id)` 汇总任务，按 `slot_index` 汇总物理尝试。不能借另一侧已恢复的字段重构本侧结果。旧 `B2 5A` 性能协议及 Sequence 规则保持兼容；当前共包采用独立的 `B2 43` v1 格式，字段及预算见[v1 负载草案](control_sync_packet_v1_draft.md)。

论文结论随测量能力确定：若要声称两类接收端达到给定同步精度，需要独立于被评估时间模型、具有明确误差界的共同参考及被测事件。无法建立该参考时，结论限定为共包时间信息分发、相对时间保持与软件调度原型。拟合残差、主机回调差值和人为输入的参考误差界不能替代实测跨设备同步误差。50 ms 可作为预先选定的粗粒度候选容差，并报告 10/100 ms 敏感性；这些不是已测得精度。

现有设备为一块发送 SDR、两块 HackRF 和主机。商用协议栈、物理执行器、共享时钟/触发附件及更多独立节点不视为已有条件；这些验证作为后续扩展。BlueBee 已有双协议广播和控制先例，exadv 共包的创新性仍需结合[先例研究](sync_control_payload_research.md)继续查新，不能仅以协议升级、字段增加或负载变大宣称贡献。

## 3. 下一阶段工作包与顺序

按 N1→N2→N3→N4/N5 推进；N3 的取时诊断可与前两项并行。对每个工作包先完成实现与一轮可审计验证，再选择主要配置做独立重复。增加已有实验的次数不能替代下列交付物。

### N1：最终跨信道配置的双端多任务实验

具体任务清单、接收接口前置工作和可复制指令见 [N1 执行方案](n1_cross_channel_experiment_plan.md)；首轮采用 Run 2001、500 ms 周期、120 槽和三项逻辑任务。

目的：在同一轮同时验证 BLE 实际跟随、IEEE 独立接收、连续时间更新和多命令解析，连接目前分散的功能证据。

- 发送端使用 `rf_mode=standard_secondary_ch3`，primary ch39、secondary BLE ch3 / IEEE ch12。复用 1801 的连续更新时间及多任务语义，按当前跨信道发送能力调整周期、槽位、有效期和执行提前量，显式记录实际参数。
- HackRF A 按 AuxPtr 从 ch39 跟随至 ch3；HackRF B 固定 IEEE ch12。两侧记录同轮 `run_id`、时隙与命令，不将 1905 的双 BLE 接收配置当作双协议实验。
- 跟随验证器已支持多任务记录，`plan_analyze.py --ble-flow` 已接入逐任务汇总所需的本侧事件；本轮使用更新后的脚本保存 CRC 证据和采集起止时间。当前跟随验证器的解析成功不自动表示已经调用实时控制调度器；报告区分解码、接受、调度和软件处理。
- 输出逐槽四象限、缺失 DID、primary 检出数、成功跟随数/计划数、成功跟随数/有效 primary 数、各任务两侧字段和联合解析率。记录迟到、过期、重复及时间质量拒绝原因。
- 保存完整板端日志与两侧逐事件数据；IEEE 保存 IQ。若增加跟随 IQ 保存，必须附切频状态和采样连续性诊断，不能默认当前跟随脚本已有 IQ。

验收交付：同轮跨信道双协议多任务报告及 CSV/JSON；失败任务保留在分母中。功能样例与可靠性统计分开，不要求用一次偶然的 100% 结果掩盖失败。若仍缺少校准参考，软件调度拒绝应如实记录。

### N2：分别发送基线与控制效率

目的：检验共包是否带来可测收益，以及收益对应的条件和代价。

1. 实现基线 A：同一发送设备分别发送 BLE 与 IEEE 802.15.4 对应任务，说明顺序发送、波形和硬件能力。不能默认额外发射机或并行发送。
2. 沿用基线 B：同包解码后立即软件处理。其功能回放已完成，后续补效果比较，统一任务、有效期及后验截止时间评价规则；不要求无时间模型的基线假装具备在线全局时间判断。
3. 实验组 C：同包携带两侧控制与时间信息，使用时间模型；参考未校准时，仅比较可直接测得的解析、成本和本侧软件指标，跨机同步指标记为未测。

对照保持相同应用语义、目标数、射频条件、截止时间和明确的重发策略。分别比较同空口预算下的联合成功率，以及达到同一可靠性目标时的成本；未达到目标的配置也保留。不同模式的格式、发送顺序和硬件差异列入配置表。

交付指标：联合有效解析任务数/计划任务数、截止时间内结果、全部 RF 发射时长/成功联合任务数、物理发送次数、请求至软件完成时延和可持续任务速率。时延必须明确请求与完成事件、时间域和校准条件；无法对齐时不报告跨机完成时延。RF 成本包含 primary、secondary、时间更新、失败尝试和重发，包间静默单列。BlueBee 编码膨胀及重复同步字段计入预算，不预设共包一定更省时或更可靠。

### N3：板端时间参考与独立同步评价

目的：区分记录延迟、DMA 准备延迟和实际空口偏差，并决定论文能报告哪一层同步结论。

- 在 primary、secondary 相同代码位置记录 DMA 调用前、提交寄存器写入前后、调用返回后的时刻，单列缓存刷新和准备耗时；必要时检查将准备移至目标等待之前的可行性。继续使用寄存器轮询与明确超时，不依赖 DMA IRQ。
- 区分提交前已错过窗口与返回后代理值越界，不将 DMA 提交、返回、完成混称为空口发射。统一空口参考点和包内 BLE/IEEE 位置差后再解释 AuxPtr 与同步字段。
- 核查 IQ 能覆盖的时间基准：1905 仅保存 ch3 IQ，1906 跟随记录未保存 IQ，不能据此测 primary→secondary 空口间隔。两台独立 HackRF 的 IQ 起点也不能直接相减；单机切频 IQ 只有在采样连续性及间隙误差得到验证后才可用于相应时间估计。
- 参考基准独立于被评估模型，校准段与验证段预先分开；不得用验证包逐包对齐两路 IQ 后将残差当作同步算法结果。单列采集零点、采样率、固定延迟及板端参考不确定度。
- 有可审计共同参考时，比较立即处理与时间模型处理的目标时刻偏差和两侧软件事件时差，报告偏差、中位数、P95、P99、最大值、CDF、有效样本和缺失数。主容差及敏感性容差在实验前固定，达标任务数以全部计划任务为分母。

验收交付：取时定义、误差预算和独立验证报告。若无法建立误差界，则将论文同步结论限定为相对时间保持和软件调度原型；假设参考界的功能回放明确标注，不作为实测精度。物理执行器动作不属于当前设备可直接验证的事件。

### N4：容量、legacy 对照与适用范围

目的：说明 exadv 单包容量解决的具体任务约束，以及负载增长何时导致失败。

- 基于当前 224 B PDU payload 工作点，逐项核算扩展头、AD 封装、35 B BLE 记录、IEEE 原始记录、映射区域、同步和校验开销；单个 PDU payload 不超过 255 B。旧性能协议的 46 B 上限不直接作为共包容量。
- 先定义可变负载的版本与校验方式，再扫描 BLE/IEEE 控制长度组合，覆盖短负载、当前工作点和接近容量边界的组合。输出字节预算、两侧及联合有效解析率、容量边界和联合成功率热力图。
- legacy 对照保持应用任务与时间语义相同，允许合理紧凑编码或分包并计入全部成本；不能仅因当前 v1 固定字段长于 legacy 容量，就判定其无法承载同任务。确实不可实现时列出具体约束，不虚构测量值。

验收交付：格式预算表、实测容量结果和可复查的对照条件，说明容量增加与可靠性、空口成本之间的关系。

### N5：机制消融、失败行为与任务结果

目的：确定收益来自哪些机制，以及失更、漏收和处理延迟如何影响任务。

- 复用 1703–1705 的方法，分别改变有效历史包数、训练跨度、更新间隔和连续失更长度；补充固定偏移、一次估频后冻结、周期更新等对照。保持验证集独立，避免只比较参与拟合的包。
- 改变命令重复次数 K、执行提前量和任务负载，记录联合解析、接受/拒绝、去重、过期、迟到、失去时间质量及任务成本。单侧漏收仍计入计划任务分母。
- 检查错误目标、未知命令、冲突字段、重复与乱序等行为，将已有单元测试、同 IQ 回放、注入掩码及真实空口观测分别列出。离线漂移或丢包注入只能作为仿真/回放证据。
- 有独立时间参考后才计算同步达标率；没有时仅报告相对预测误差及本侧软件事件，不能将接受或解析计数替代同步成功。

验收交付：参数—效果—成本曲线与失败案例表。先做少量有解释力的配置，避免同时修改多项参数而无法归因。

## 4. 统一归档与统计要求

每轮保存完整板端命令和逐槽统计、代码/固件版本、两侧设备与 RF/USB 配置、独立逐包及逐任务记录、时间参考定义、处理异常、CSV/JSON 和关键 IQ。沿用 `python/experiments/YYYYMMDD_run<run_id>/`；人工观察写入 `notes.md`，联合分析放入 `analyses/`。输入 IQ 的重复分析不增加独立实验轮数。

所有比率给出分子/分母，零分母为 `N/A`。逐槽报告双方成功、仅 BLE、仅 IEEE、双方失败；逐任务按命令去重，另报一次发送、重复 K 次和截止时间内结果。条件误差分布须附全部计划任务数、失败和缺失数，不能只保留成功子集。

主要配置至少三轮独立重复，交替对照顺序，报告逐轮结果、样本数与置信区间；相关连续丢包不无说明地当作独立样本。1703–1705 的既有重复仍有效，但不能代替新跨信道配置或新基线的重复。检查饱和、USB/主机丢样、队列积压及截断；无告警不等于已证明连续无丢样，无法归因的失败标为原因未定。

## 5. 最近一个可执行动作

先准备 N1 的跨信道双端多任务实验：核对当前发送能力和接收器接口，编写一轮明确的任务/时隙清单，安排 BLE 跟随与 IEEE ch12 同时独立接收，并补齐逐任务联合报告。随后实现 N2 的分别发送基线；并行完善 N3 的板端取时，决定后续同步指标可用的参考。N4/N5 的小范围扫描完成后，对论文选定的主要配置增加重复。

当前阶段的完成条件是：有同轮最终配置的双协议功能证据，有公平基线的实际收益或代价结果，有与测量能力一致的时间结论，以及容量/机制/失败边界。商用芯片、执行器和多节点扩展不作为现有设备下必须完成的前置项。裸机构建与上板由用户执行；`app_FreeRTOS/` 的源码修改须同步到 SDK 实际编译目录后再验证。
