## H1 同 IQ 与 H5 失更

将 2704（A）和 2718（B）的 BLE 原 IQ 送入 IEEE 独立解码链，均获得 10/10 条有效命令。按同一 IQ 的 `sample_start` 相减，A 点差值 400.00–400.25 µs、中位数 400.25 µs；B 点 608.00–608.25 µs、中位数 608.00 µs，符合 `400+8b` 的布局预测。这是同一采样时钟下的字段位置证据，不是两块 HackRF 的绝对同步精度。解码输出保存在 2704、2718 各自的 `analyses/h1_same_iq_ieee/`。

2716 BLE 侧在本侧 IQ 约 60.31 s 进入 holdover、68.30 s stale、84.31 s reacquiring、91.31 s 恢复 tracking；2717 IEEE 侧对应约 60.36、68.35、83.36、92.36 s。非受影响侧 24/24 留出探测均有记录；受影响侧均为 19/24。录制尾段的 stale 是板端停止后的现象，不计作人工干预。2716/2717 均有 1 个任务单侧漏收；这说明单侧失更与重获路径可见，不能声称真实执行或跨设备时钟精度。

## P2 截止期方法审计

- 两块 HackRF 的 IQ 采样索引只在各自录制内构成相对时间轴；尚无共同 RF 起点或外部参考误差界。每侧接收链的 `available_sample` 是记录完整后可用的本侧样本位置；LC/C3 任务必须以该槽**最后一片完成重组**后的可用位置判断，不能以第一片或串口打印时刻代替。
- 板端计划槽、DMA 完成和波形预算均不能给出真实 RF 发射起止的已校准界；USB 丢样、队列溢出或截断会进一步削弱本侧时间轴连续性。现有 2701–2718 数据未建立可审计的外部参考界，也没有可用于校准并独立留出验证的 RF 时基。因此逐任务 `deadline_class=unknown` 保留，不能将“计划尝试内联合解析”写成“截止期内联合交付”。
- P3 冻结前须在[当前研究计划](../paper/current_research_plan.md)中将相应论文结论限定为“限定计划尝试的联合解析”；若以后取得独立参考界，应另设校准/留出验证并重新审计截止期，不能逐包用待测 slot 自我对齐。

## 2711–2714 后续校正分析

新增分析器显式选项 `--reconcile-board-budget` 后，四轮分别生成 `analyses/uc1_board_budget_reconciled_v2/`。该选项只允许 core、原 manifest 为显式 K、板端预算大于原分配成本，且 `floor(Q/C)=K` 与板端未用预算吻合；其他不一致仍拒绝。报告保留原 manifest 哈希和接收端配置哈希，预算/未用量取板端原始日志，不改写原文件。

四轮联合解析均为 10/10；板端 Q=6000 µs，每任务未用预算分别 176/432/432/192 µs。板端 `UC1_CONFIG` 的模式、profile、任务数、槽数、K、每次成本、布局、周期与捕获 manifest 一致；`floor(Q/C)=K`、`Q-KC=unused` 也逐轮吻合，逐任务身份匹配，两侧接收摘要仍绑定原 manifest。输出策略标记为 `board_budget_reconciled`。这些独立一致性检查足以认定 H4 的**实际发送配置与 P2 预期等效**，四轮作为 P2-H4 初验通过。由于原始板端命令未独立保存，不能声称捕获时的 manifest 本身完全正确；比较器保留 `reconciliation.policy_command` 缺证，自动协议可靠性归因仍不授予。P4 正式同预算重复须从采集前生成 `--policy budget --value 6000` 的一致 manifest，并保存导出的板端命令与同轮配置哈希。

复现示例（2712；其他三轮更换 run_id 与日期，分析目录必须是新名称）：

```bash
python3 python/control_match/uc1_analyze.py \
  --experiment-dir python/experiments/20261120_run2712 \
  --config python/control_match/configs/uc1_2712.json \
  --analysis-id uc1_board_budget_reconciled_v2 \
  --reconcile-board-budget
```

1. **H1 C 点（2707）同 IQ 偏移复核**：将 2707（C 点，`b=2, z=6`）保留的 BLE 原始 IQ 送入 IEEE 独立解码链，保存至 [h1_same_iq_ieee](../../python/experiments/20261120_run2707/analyses/h1_same_iq_ieee/zigbee/rx.summary.json)。获得 **10/10** 条有效命令；同一 IQ 下 `sample_start` 差值范围 **416.00–416.25 µs**、中位数 **416.25 µs**，符合配置布局预测 `400 + 8×2 = 416 µs`。至此 H1 实录同 IQ 验证覆盖全部三个代表布局点（A：`400.25 µs`、C：`416.25 µs`、B：`608.00 µs`）；此证据仍仅证明同一采样时钟下的包内字段相对位置，不构成两块 HackRF 跨设备同步精度。

**冻结判断**：H1–H6 的 P2 桥接初验均有通过依据，P2 结果可按“初验完成、带 H4 配置溯源例外”归档冻结，无须为关闭 P2 重做 2711–2714。H6 属于实录包流上的合成注入，不能写成空口异常实测。当前代码通过 143 项单元测试，并有上述实录回放，可作为**候选冻结版本**；进入 P3 前将板端源码、接收与分析代码及配置固定到可追溯的提交/哈希。2711–2714 不作为配置完全一致的 P4 确认性重复，也不能仅凭全收结果证明同预算可靠性收益；P4 新采集须使用正确的预算 manifest 与导出的板端命令。`R1` 天线条件摸底可作为先导开展，不能事后改称确认性重复。
