# 1703–1704 双接收端时间保持阶段复核

两轮均为同频诊断共包、受控馈线、两块独立 HackRF、4 Msps、200 ms 周期、预设 300 个槽。两侧各自完成 PHY 和应用校验，并在每轮的固定 168 个验证槽都真实恢复了包；不同包训练与失更是**离线掩码**。1702 的 8 Msps 录制有采样时间轴跳变，只作故障诊断，不与这两轮合并。

| 指标 | 1703 | 1704 |
|---|---:|---:|
| BLE / IEEE 有效时间记录 | 300 / 300 | 300 / 300 |
| 同槽双方有效 | 300/300 | 300/300 |
| 板端 secondary DMA 完成 | 300/300 | 300 / 300 |
| 两侧最大相邻间隔偏差 | 0.918 / 0.918 ms | 0.9935 / 0.99375 ms |
| 不同包、2 点训练并冻结：绝对相对差中位数 | 27.48 ms | 33.89 ms |
| 不同包、10 点训练并冻结：绝对相对差中位数 / P95 | 1.87 / 3.59 ms | 1.58 / 3.07 ms |
| 不同包、10 点训练、每 1 s 更新：中位数 / P95 | 0.133 / 0.392 ms | 0.138 / 0.376 ms |

两轮方向一致：在本组受控记录中，短跨度两点估频后长期失更会放大相对估计差；历史点增多或周期更新可降低误差。这是**两个独立物理录制轮次上的离线时间模型复测**，不是实际丢包后的在线成功率。1704 没有匹配的板端最终/逐槽日志，不能为它报告相对于板端完成数的 PRR；两轮均无实测 RF 起点、共享采集触发或执行器动作。因此当前足以继续做共包时间更新与命令混合的功能实验，不足以给出绝对同步或同步执行精度和稳定尾部误差界。

逐轮原始口径见 [1703 报告](../python/experiments/20261109_run1703/analyses/holdover_preregistered_v2/report.md)与 [1704 报告](../python/experiments/20261109_run1704/analyses/holdover_preregistered_v1/report.md)。下一项具体操作见[连续时间更新与控制计划](integrated_sync_control_experiment_plan.md)。
