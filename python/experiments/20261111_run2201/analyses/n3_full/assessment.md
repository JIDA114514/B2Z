# 2201 N3 首轮评估

## 结论

本轮完成了固定频点双接收链的 300 槽记录，且 N3 因果回放按预登记的 24 个留出探测槽全部评分。它支持“当前 SDR 接收与离线时间保持分析链可运行”的首轮功能结论；不能证明绝对时钟同步、实际 RF 发射时刻或执行器同步。

## 数据完整性

- 板端计划 300 槽、500 ms 周期，实际运行 150.000005 s；generated/primary_started/primary_completed/tx_started/tx_completed 均为 300，`deadline_miss=0`、`dma_timeout=0`。
- `CONTROL_TIME_END` 显示 300 槽、`overflow=0`；取时日志完整，所有已记录阶段状态为 0。
- BLE 与 IEEE IQ 均为 4 Msps、180 s、720,000,000 samples；接收程序正常结束，队列未溢出、未报告削顶。
- BLE CRC/扩展头有效 300/300；IEEE FCS 与控制记录有效 300/300；按槽关联双方均有效 300/300，计划槽缺失 0。
- 本轮无控制任务（command_id=0），因此不能计算任务执行成功率或单位成功任务成本。

## 时间保持回放

## 发现的板端 AuxPtr 窗口问题

固件配置为 `aux_offset_us=300000`、`B2Z_AUXPTR_WINDOW_US=300`。逐槽结果显示 `auxptr_dma_window_miss=300/300`。取时轨迹中的 primary 与 secondary 同位置 `submit_write` 的间隔中位数约 300.883 ms、P95 约 300.892 ms，即超过 300 ms 目标约 0.883/0.892 ms；所有槽都晚于代码检查的目标后 300 µs 窗口。

轨迹同时显示 secondary `cache_flush` 中位数约 975 µs，secondary DMA 启动调用总时长中位数约 982 µs。它与提交越窗的量级相符，是优先排查的候选原因：当前等待逻辑到 AuxPtr 目标附近后才进入 DMA 启动路径，缓存刷新发生在实际提交之前。此关联不能替代 RF 空口测量。secondary 固定信道仍被 BLE 接收机完整解码 300 个，因此本轮证明了固定频点 secondary 内容接收；没有证明 primary AuxPtr 与空口 secondary 起始满足标准跟随时序。BLE 报告中的 `strict AuxPtr matched=0` 是因为该次接收固定在 secondary 信道，没有同时捕获 primary；不能单独据此判断 AuxPtr 错误，板端的 300 次窗口越限则是独立证据。

## 解释边界与数据核查项

- `secondary_dma_late_us` 中位数约 80.187 ms，`generation` 阶段中位数约 79.181 ms。前者是相对计划槽时间的板端软件代理值，和波形生成耗时量级接近；它不表示每个包在 primary→secondary 间隔内晚了 80 ms，也不是测得的 RF 发射偏差。
- 时间保持使用标称 4 Msps 样本率及包内已知标记映射。两路 IQ 的采集起点没有硬件校准，USB 队列未溢出也不证明 IQ 全程无丢样。
- 已复核两份原始摘要：BLE serial 为 `000000000000000017c467dc2926a0c3`，IEEE serial 为 `000000000000000017c467dc3348a6c3`，两者不同。此前评估中“相同 serial”的判断是读取错误，已纠正。

## 建议的后续步骤

1. 先拆分 secondary DMA 准备与提交：在 AuxPtr 等待前完成并验证缓存刷新/缓冲准备，窄窗口内只做必要的寄存器提交；板端逐槽应达到 `auxptr_dma_window_miss=0` 后，再做 primary 与 secondary 同步 IQ 或真实跟随核查。
2. 使用同样的两台接收设备与配置，保留两条接收启动命令和固件版本。
3. 修正后重复 2201 完整采集；至少先检查全部 300 槽是否在软件窗口内，再比较 holdover。保持当前 2201 为首轮结果，不覆盖或删除。
4. 重复轮次中继续冻结相同探测槽和配置，并报告每轮结果；若目标是实际漏收容忍，再安排真实单侧漏收实验，不用离线掩码替代。
